# 飞书 Bot 生命周期 SOP

适用范围：OPC 内部飞书自建应用 / 机器人从 0 配置、权限申请、改名换头像、发布更新、拉群和验证。本文是 OPC 项目事实源；系统级 Codex skill 只能引用本文，不另立一套权威流程。

## 核心原则

- 聊天记录跟 App ID / 机器人身份绑定，不跟显示名称或头像绑定。
- 要保留原聊天记录，必须在原应用上改名、换头像和发布版本；不要新建应用替代原应用。
- 开放平台里改好名称和头像，不等于飞书客户端立刻生效；看到“版本发布后，当前修改方可生效”时，必须创建版本并确认发布。
- 不记录、复制或传播 App Secret、token、cookie、private key、session。
- 可以记录 App ID、应用名、对应 Hermes profile、可用范围和发布状态。
- 涉及外部可见承诺、客户群、客户隐私、报价、交付范围或声誉风险时，先升级夏董拍板。

## 从 0 创建 Bot

1. 进入飞书开放平台，创建企业自建应用。
2. 设置应用名称、头像和描述。
3. 添加机器人能力。
4. 配置需要的权限、事件与回调、安全设置。
5. 记录 App ID 与对应 Hermes profile；不要记录 App Secret 原文。
6. 在 Hermes / gateway 配置中完成对应 profile 的飞书连接。
7. 启动或重启 gateway 后，确认日志出现飞书连接成功，并做一次私聊测试。

## 改名和换头像

1. 先确认要改的是原应用，而不是新建应用。
2. 在“凭证与基础信息”中修改应用名称、应用图标。
3. 检查“机器人”能力页是否存在单独的机器人展示名称或头像配置；如有，也要同步修改。
4. 回到基础信息页，确认顶部是否提示“版本发布后，当前修改方可生效”。
5. 进入“版本管理与发布”，创建新版本。
6. 默认能力选择“机器人”，更新说明可写“更新应用版本”或更具体的变更说明。
7. 保存版本，并在确认弹窗中点“确认发布”。
8. 发布后确认页面显示“当前修改均已发布”或版本状态为“已发布”。

## 保留聊天记录的检查

发布前必须确认：

- App ID 没变。
- 没有把旧应用停用后改用新应用。
- Hermes / gateway 配置仍指向原 App ID / 原机器人身份。
- 飞书客户端里的旧会话还在原聊天列表中。

如果已经误建了新应用：

- 不要用新应用替代旧应用来承接原聊天记录。
- 优先把旧应用改成目标名字和头像，再发布。
- 新应用可改名为“归档 / 勿用”或停用，避免后续点错。

## 发布后验证

1. 开放平台：确认版本状态为“已发布”，顶部显示“当前修改均已发布”。
2. 飞书客户端：退出并重新打开飞书，重新搜索 Bot 名称。
3. 私聊：给 Bot 发一条测试消息，确认 gateway 能收到并回复。
4. 群聊：将 Bot 拉入目标群，确认群内 @Bot 或触发方式可用。
5. 日志：确认对应 profile 的 gateway 日志显示连接成功和消息收发正常。

## 拉群与群聊验证

- 拉群前确认该 Bot 的可用范围包含相关成员或群。
- 如果群聊需要 @ 才响应，确认 gateway 的 Bot 名称与飞书开放平台 / 飞书客户端实际显示名一致。
- 如果日志提示 `FEISHU_BOT_NAME differs from /bot/v3/info`，以飞书接口读取到的实际 Bot 名称为准，同时检查本地配置是否需要同步。
- 群聊首次测试只发内部测试消息，不放客户隐私、报价或外部承诺。

## 常见问题

### 开放平台已经改名，飞书客户端没变

优先检查是否还没发布版本。只改基础信息但未发布时，飞书客户端通常仍显示旧名旧头像。

### 发布后仍没变

先等待几分钟，再退出飞书客户端重新打开；必要时重新登录或清缓存。确认开放平台不是“待申请”或“未发布”状态。

### 聊天记录会不会丢

同一个 App ID 上改名、换头像、发布版本，不会迁移或删除原会话记录。新建应用则是新的机器人身份，旧聊天记录不会自动合并过去。
