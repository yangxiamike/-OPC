# Feishu @提及触发规范 v0.1

更新时间：2026-05-19
适用范围：OPC 内部 Agent 协作群（含 CEO/PM、董秘及员工 Agent）

## 1) 结论（必须执行）
在 OPC 群内给 Agent 下达需要“被处理/被回复”的指令时，必须使用 **真实 mention 格式**：

```text
<at user_id="OPEN_ID">显示名</at> 指令内容
```

禁止仅使用纯文本 `@名字` 作为可靠触发手段。

## 2) 背景原因
当前协作网关默认策略为 `FEISHU_REQUIRE_MENTION=true` 且 `FEISHU_ALLOW_BOTS=mentions`。
在该策略下，只有可识别的 mention 实体才能稳定触发处理链路；纯文本 `@名字` 可能仅视觉上像@，但不会进入目标 Agent 的有效触发流。

## 3) 标准写法
### 周成 CEO
```text
<at user_id="OPEN_ID_OF_MAX_CEO">周成 CEO</at> 请回执：已收到，今日按新口径执行。
```

## 4) 最小执行要求
- 下发任务：必须真实 mention + 明确动作。
- 要回执：消息中包含“收到请回执”。
- 判完成：以“已回执 + 有可验证动作/结果”为准，不以“消息已发出”为完成。

## 5) 异常处理
若发送后未回执：
1. 先检查是否用了 `<at user_id="...">...</at>`。
2. 再做二次催办（仍用真实 mention）。
3. 仍无回执时，按“未响应”升级处理，不得口头判定已执行。
