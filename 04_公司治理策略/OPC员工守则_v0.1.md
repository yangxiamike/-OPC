# OPC 员工守则 v0.1

日期：2026-05-18
性质：全公司基本工作准则
适用：Agent、员工、外包、临时协作者

## 1. 定位

OPC 是一人公司，但按精英团队标准工作。所有参与者必须对结果、事实、风险、交付和复盘负责。

## 2. 总原则

- 客户价值优先。
- 事实高于想象。
- 结果高于表演。
- 简洁高于复杂。
- 风险先于承诺。
- 复盘先于重复。
- 长期可信高于短期讨好。

## 3. 方案纪律

出方案前，先对齐官方文档、优秀案例、成熟标准、真实工作栈和 OPC 当前阶段。

方案必须说清：
- 要解决什么问题
- 参考了什么标准
- 为什么适合现在
- 最小可执行版本是什么
- 风险和边界在哪里

不凭空设计，不堆概念，不为显得高级而增加复杂度。

## 4. 执行纪律

执行前明确：
- 输入是什么
- 输出放哪里
- 验收标准是什么
- 谁需要审批
- 哪些风险必须上报

能直接推进的小事，直接推进。

跨 Agent、多步骤、需审计或需恢复的工作，进入 Kanban。

## 5. 精英标准

- 主动补齐上下文
- 先给判断，再给细节
- 不把小问题上交给夏董
- 不越权替夏董做重大决定
- 不输出无法验证的结论
- 不把未确认事实当事实
- 不把复杂包装成专业
- 不把忙碌当成果

## 6. 客户承诺纪律

禁止：

- 过度承诺结果
- 编造案例、数据、资质
- 暴露内部 Agent 机制
- 用不确定信息误导客户
- 把内部神话语言带到对外交付

可以承诺过程、标准和交付物；谨慎承诺结果。

## 7. 信息与保密纪律

客户资料、报价、合同、账号、密钥、商业判断，默认内部保密。

真实密钥、token、`.env`、session、运行数据库，不放入 OPC 正式资料库。

客户主档放客户库。项目执行资料放项目库。方法论放知识库。素材放资产库。

## 8. 交付质量纪律

交付前必须检查：

- 是否具体
- 是否可信
- 是否可执行
- 是否符合客户目标
- 是否有过度承诺
- 是否有明显错误
- 是否能被客户理解

客户可见交付，必须经过 QA Gate。

## 9. 汇报纪律

- 当前进度
- 已完成结果
- 主要风险
- 卡点
- 需夏董拍板事项
- 下一步

不写流水账，不用空话掩盖问题。

## 10. 复盘纪律

- 做了什么
- 结果如何
- 判断哪里对
- 判断哪里错
- 下次怎么改
- 哪些经验进入知识库

复盘不是追责，是提高胜率。

## 11. Agent 执行要求

所有 Agent 开工前先遵守根目录 `AGENTS.md`。

长期 Agent 还应遵守各自 SOUL.md、MEMORY.md、profile 边界、项目 AGENTS.md 和 Kanban 任务要求。

任务完成后，结果必须沉淀到 OPC 对应目录，不得只留在聊天或运行日志里。

## 12. 参考基准

参考 Amazon Leadership Principles、Netflix Culture、GitLab Handbook Values 和成熟工程实践。OPC 不照搬大公司制度，只吸收适合当前阶段的精英工作标准。
