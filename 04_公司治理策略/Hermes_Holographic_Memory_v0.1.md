# Hermes Holographic Memory 启动规则 v0.1

日期：2026-05-18
状态：试运行版
定位：Hermes Agents CLI 启用 Holographic Memory 的最小规则
上位依据：董事会第 1 号决议《一人公司集团运行系统 v0.1》

## 1. 定义

Holographic Memory 是 Hermes 自带的记忆能力，不另行重造系统。

本文件只负责说明：

- 启动时要开启 Holographic Memory。
- 它服务哪些 Agent。
- 哪些内容可以记。
- 哪些内容不能记。
- 记忆与 OPC 文件冲突时听谁的。

## 2. 启动要求

搭建 CEO 团队时，Hermes Agents CLI 应为以下核心 Agent 启用 Holographic Memory：

- CEO / PM Agent。
- Research / Intelligence Agent。
- Strategy / Conversion Agent。
- Design / UX Agent。
- Development & Test Agent。
- QA / Gate Agent。

每个长期 Agent 使用独立 profile、独立 SOUL.md、独立 MEMORY.md 和独立记忆空间。

不要让所有 Agent 共用同一个记忆库，除非夏董另行批准。

## 3. 记什么

Holographic Memory 只记录对未来执行有帮助的稳定信息：

- 夏董稳定偏好。
- Agent 角色边界。
- 项目历史摘要。
- 客户偏好摘要。
- 复盘后的有效经验。
- 反复出现的协作问题。
- 已验证的行业观察。

临时闲聊、一次性任务、未经验证的猜测，不进入长期记忆。

## 4. 不记什么

未经夏董明确授权，不写入：

- 密码、token、API key、cookie、私钥。
- 收款账户、付款凭证、财务敏感信息。
- 客户未公开的商业秘密。
- 个人隐私信息。
- 未确认的报价、承诺、折扣、交付期限。
- 对外可能造成误导的团队规模、身份或案例。

## 5. 权威顺序

如果 Holographic Memory 与正式文件冲突，以正式文件为准。

顺序如下：

1. 夏董当次明确指令。
2. 董事会决议。
3. CEO 任务输入。
4. 公司治理策略与员工守则。
5. 项目库文件。
6. Agent SOUL.md / MEMORY.md。
7. Holographic Memory 检索结果。

一句话：

> OPC 是事实源，Holographic Memory 是辅助记忆。

## 6. 与 Hermes Agents CLI 的关系

托特秘书与 Hermes Agents CLI 沟通时，只需要传达：

- 启用 Holographic Memory。
- 按 Agent 隔离记忆。
- 不把敏感信息写入记忆。
- 不让记忆覆盖 OPC 正式文件。
- 需要长期生效的规则，先写回 OPC，再同步给 Agent。

CLI 负责运行记忆能力；OPC 负责保存公司事实。

## 7. 试运行复盘

先按本规则试运行。

复盘时只检查三件事：

1. 记忆有没有让 Agent 更稳。
2. 记忆有没有污染角色或制造误判。
3. 哪些经验需要从记忆提炼回 OPC。

## 8. 定案

当前版本不建设额外 Memory 系统。

只启动 Hermes 自带 Holographic Memory，并用 OPC 的正式文件守住边界。
