# 董事会第 1 号决议：一人公司集团运行系统 v0.1

日期：2026-05-18
状态：已通过
决议编号：董事会第 1 号决议
决议级别：集团运行内核决策
归档位置：董事会决议
尺度审计：战役级，通过。本决议定义公司如何运行，不拆解 CEO 团队内部 Kanban，不预设执行团队日程。

## 1. 决议名称

本期战役正式命名为：

> 一人公司集团运行系统 v0.1

本决议是公司第一个上位运行决议，用于确立董事会、Codex、Hermes CEO Agent、执行 Agent、Memory 与文档系统之间的基本协作秩序。

## 2. 编号校正

董事会确认：

- 本决议作为董事会第 1 号决议。
- 2026-05-17 形成的《外贸阀门工厂官网改造获客战役 v0.1》编号校正为董事会第 2 号决议。
- 第 2 号决议不作废，但应在第 1 号决议确立的运行系统下重新接入执行。

编号逻辑：

> 第 1 号决议定义公司如何运行；第 2 号决议定义公司先做什么业务。

## 3. 决策背景

公司已经形成初步业务方向和 Hermes Agent 执行团队设想，但在正式推进 MVP / 获客战役前，必须先确认上位运行系统。

若先启动业务执行，而不先定义组织、权限、记忆和文档流转规则，后续容易出现：

- 董事会文件越级变成执行 Kanban。
- CEO 团队角色边界不稳。
- Agent Soul 设定彼此污染。
- Memory 沉淀过度、混乱或越权。
- 业务项目与公司治理文件混杂。
- OA 系统一次性做大，拖慢现金流验证。

董事会判断，当前优先事项不是建设完整 OA 平台，而是先形成可运行、可复盘、可扩展的最小集团运行内核。

## 4. 董事会目标

本阶段目标：

> 跑通“夏董愿望 -> 董事会尺度审计 -> CEO 接收 -> Agent 执行 -> Memory 沉淀 -> 复盘回传”的最小闭环。

本目标服务于后续所有业务项目，包括但不限于第 2 号决议所涉及的外贸官网改造获客战役。

董事会关注的是：

- 组织角色是否清楚。
- 董事会与 CEO 团队是否各司其职。
- Agent Soul 是否可注入、可约束、可复用。
- Memory 配置是否克制、安全、可维护。
- 文档系统是否能承载立项、派发、复盘。
- 是否避免为了系统而系统，拖慢业务验证。

## 5. 本阶段核心资产

本阶段只建设四个核心资产：

1. CEO 团队组织宪章。
2. Agent Soul 注入协议。
3. Memory 配置规则。
4. 董事会-CEO 协作与 OA 文档规程。

上述资产必须服务真实执行闭环，不追求抽象完备。

## 6. 授权范围

董事会授权 Hermes CEO Agent 在本决议范围内，整理并提交集团运行系统 v0.1 的执行方案。

CEO Agent 可自行决定：

- 如何组织对现有 Hermes 团队结构的复核。
- 如何归纳 Agent Soul 注入所需字段。
- 如何提出 Memory 分层与写入边界。
- 如何设计董事会到 CEO 的文件流转建议。
- 如何命名内部执行项、安排协作顺序和收集材料。

董事会不预设具体 Agent 提示词全文、不预设飞书字段细节、不预设 Kanban 卡片、不预设日程节奏。

## 7. 边界与不做事项

本阶段暂不做：

- 完整 OA 软件开发。
- 复杂权限系统。
- CRM / SaaS / 客户管理平台。
- 自动化审批流。
- 大规模 Agent 招募或部门扩张。
- 把所有公司文件一次性重写。
- 将 Memory 作为无差别资料仓库。

OA 系统 v0.1 先以本地文档、项目库、治理策略和 CEO 任务输入为承载，不急于产品化。

## 8. 验收口径

本阶段以制度资产和闭环可运行为验收：

- 形成 CEO 团队组织宪章 v0.1。
- 形成 Agent Soul 注入协议 v0.1。
- 形成 Memory 配置规则 v0.1。
- 形成董事会-CEO 协作与 OA 文档规程 v0.1。
- 第 2 号决议能够在上述规则下重新接入 CEO 团队。

董事会只验收规则是否能约束行为、降低混乱、支撑执行，不验收 CEO 内部拆解细节。

## 9. 必须提交董事会确认的事项

以下情况必须提交董事会确认：

- 改变董事会、Codex、CEO Agent 的基本权责。
- 新增、取消或重组 Hermes 核心 Agent 角色。
- 将 Memory 规则扩展到敏感信息、客户承诺、账号凭证或个人隐私。
- 建设超出文档系统范围的 OA 软件或自动化系统。
- 对第 2 号决议的目标、边界或交付标准产生影响。
- 可能造成角色污染、越权承诺、成本失控或业务推进延迟的重大设计。

## 10. 复盘节点

建议在以下节点进行董事会复盘：

- CEO 提交集团运行系统 v0.1 执行方案后。
- 四个核心资产形成初稿后。
- 第 2 号决议重新接入 CEO 团队前。
- 第 2 号决议首次回报后，检查运行系统是否有效。
