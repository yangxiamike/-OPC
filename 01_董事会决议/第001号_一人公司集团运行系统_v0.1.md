# 董事会第 1 号决议：OA 系统、Hermes 经营团队结构与 Holographic Memory v0.1

日期：2026-05-18
状态：已通过
决议编号：董事会第 1 号决议
决议级别：王座层基础系统决策
归档位置：董事会决议
尺度审计：战役级，通过。本决议定义公司底层运行系统与 Hermes 经营团队结构，由董事长与托特秘书层审议确立，并由托特秘书承办搭建；不下放 CEO 决策，不拆解 CEO 团队内部 Kanban，不预设执行团队日程。

## 1. 决议名称

本期战役正式命名为：

> 一人公司基础运行系统 v0.1：OA + Hermes 经营团队 + Holographic Memory

本决议是公司第一个上位运行决议，用于确立董事会、托特秘书、Hermes 经营团队（含未来 CEO / PM Agent 与各职能 Agent）、OA 文档系统与 Holographic Memory 之间的基本协作秩序。

董事会确认：本决议所涉事项属于王座层制度资产与组织搭建资产，不属于 CEO Agent 可自行定义的经营事项。在 CEO 尚未招募或启用前，由托特秘书承办执行；CEO Agent 到位后可以参与试运行、提出反馈、承接业务接入，但不得拥有最终定义权。

## 2. 编号校正

董事会确认：

- 本决议作为董事会第 1 号决议。
- 2026-05-17 形成的《外贸阀门工厂官网改造获客战役 v0.1》编号校正为董事会第 2 号决议。
- 第 2 号决议不作废，但应在第 1 号决议确立的运行系统下重新接入执行。

编号逻辑：

> 第 1 号决议定义公司如何运行；第 2 号决议定义公司先做什么业务。

## 3. 决策背景

公司已经形成初步业务方向和 Hermes Agent 执行团队设想，但在正式推进 MVP / 获客战役前，必须先确认上位运行系统。

若先启动业务执行，而不先定义组织、权限、记忆和文档流转规则，后续容易出现：

- 董事会文件越级变成执行 Kanban。
- CEO 团队角色边界不稳。
- Agent Soul 设定彼此污染。
- Holographic Memory 沉淀过度、混乱或越权。
- 业务项目与公司治理文件混杂。
- OA 系统一次性做大，拖慢现金流验证。

董事会判断，当前优先事项不是把四个制度文件交给 CEO 决定，也不是建设完整 OA 平台，而是先由董事长与托特秘书确立三套可运行、可复盘、可扩展的底层系统，并把 Hermes 经营团队的角色结构搭建到可试运行状态。

## 4. 董事会目标

本阶段目标：

> 跑通“夏董愿望 -> 董事会尺度审计 -> 董秘承办 -> OA 归档 -> Hermes 经营团队接收 -> Agent 执行 -> Holographic Memory 沉淀 -> 复盘回传”的最小闭环。

本目标服务于后续所有业务项目，包括但不限于第 2 号决议所涉及的外贸官网改造获客战役。

董事会关注的是：

- 组织角色是否清楚。
- 董事会、托特秘书与 CEO 团队是否各司其职。
- Hermes 经营团队是否已形成可试运行的岗位结构。
- Hermes Agent 的 Soul 是否可注入、可约束、可复用。
- Holographic Memory 配置是否克制、安全、可维护。
- OA 文档系统是否能承载立项、派发、复盘。
- 是否避免为了系统而系统，拖慢业务验证。

## 5. 本阶段核心系统

本阶段只确立三套核心系统：

1. OA 系统 v0.1：承载董事会决议、CEO 任务输入、项目库、治理策略、复盘与归档。
2. Hermes Agent 系统 v0.1：承载 Hermes 经营团队结构、CEO / PM 与职能 Agents 的职责边界、Soul 注入与协作规则。
3. Hermes Agent Holographic Memory v0.1：承载公司使命、董事长偏好、历史决策、执行风格、复盘经验与上下文索引。

上述系统必须服务真实执行闭环，不追求抽象完备。

原“CEO 团队组织宪章、Agent Soul 注入协议、Memory 配置规则、董事会-CEO 协作与 OA 文档规程”降为三套系统下的子文件或子模块，不再作为彼此割裂的四个核心资产。

## 6. 授权范围

董事会授权托特秘书根据本决议起草并固化三套底层系统的 v0.1 文档，并承办搭建 Hermes 经营团队的 v0.1 运行骨架，包括核心岗位、Profile、SOUL、协作边界与试运行交接口径。董事长保留最终确认权。

在 Hermes CEO Agent 尚未招募或启用前，第 1 号决议不交给 CEO 执行；由托特秘书作为临时承办人推进到可验收状态。

Hermes CEO Agent 的授权范围调整为未来试运行与反馈，不负责定义底层制度。CEO Agent 可在制度与团队骨架确立后自行决定：

- 如何在 Hermes Agent 系统下组织内部执行。
- 如何按既定 Soul 与 Holographic Memory 规则调用执行 Agents。
- 如何把董事会任务输入转化为项目 Kanban。
- 如何收集试运行中暴露的问题并回报董事会。
- 如何让第 2 号决议接入 OA 与 Hermes Agent 系统。

董事会不预设具体 Agent 提示词全文、不预设飞书字段细节、不预设 Kanban 卡片、不预设日程节奏。

但董事会明确：CEO Agent 不得自行改写 OA 系统、Hermes Agent 系统、Holographic Memory 的基本原则、权责边界与记忆写入规则。

## 7. 边界与不做事项

本阶段暂不做：

- 完整 OA 软件开发。
- 复杂权限系统。
- CRM / SaaS / 客户管理平台。
- 自动化审批流。
- 大规模 Agent 招募或部门扩张。
- 把所有公司文件一次性重写。
- 将 Holographic Memory 作为无差别资料仓库。

OA 系统 v0.1 先以本地文档、项目库、治理策略和 CEO 任务输入为承载，不急于产品化。

## 8. 验收口径

本阶段以制度资产和闭环可运行为验收：

- 形成 OA 系统 v0.1 的文档规程与归档结构。
- 形成 Hermes 经营团队 v0.1 的组织结构、Profile / SOUL、职责边界与协作规则。
- 形成 Hermes Agent Holographic Memory v0.1 的分层、写入、读取、更新与禁区规则。
- 第 2 号决议能够在上述规则下重新接入 Hermes 经营团队，并在 CEO Agent 到位后由其承接经营调度。

董事会只验收三套系统是否能约束行为、降低混乱、支撑执行，不验收 CEO 内部拆解细节。

## 9. 必须提交董事会确认的事项

以下情况必须提交董事会确认：

- 改变董事会、托特秘书、CEO Agent 的基本权责。
- 新增、取消或重组 Hermes 核心 Agent 角色。
- 将 Holographic Memory 规则扩展到敏感信息、客户承诺、账号凭证或个人隐私。
- 建设超出文档系统范围的 OA 软件或自动化系统。
- 对第 2 号决议的目标、边界或交付标准产生影响。
- 可能造成角色污染、越权承诺、成本失控或业务推进延迟的重大设计。

## 10. 复盘节点

建议在以下节点进行董事会复盘：

- 托特秘书提交三套底层系统 v0.1 初稿后。
- 托特秘书完成 Hermes 经营团队 v0.1 运行骨架后。
- CEO Agent 到位并完成第一轮试运行反馈后。
- 第 2 号决议重新接入 Hermes 经营团队前。
- 第 2 号决议首次回报后，检查运行系统是否有效。
