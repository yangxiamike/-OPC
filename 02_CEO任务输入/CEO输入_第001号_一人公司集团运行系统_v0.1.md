## 3. CEO 经营权限

CEO Agent 在董事会授权范围内自行管理：

- 内部调研和材料归纳。
- 执行团队结构复核。
- Agent Soul 字段设计建议。
- Memory 分层与写入规则建议。
- 董事会-CEO 文件流转建议。
- 内部任务拆解、协作顺序和质量检查。

上述事项属于经营执行细节，不需要作为过程材料提交董事会。

CEO Agent 不得自行改变董事会、Codex、CEO Agent 的基本权责，不得擅自扩建完整 OA 软件，不得把 Memory 设计为无差别资料仓库。

## 4. 第一轮交付

CEO Agent 第一轮必须提交实质成果：

1. CEO 团队组织宪章 v0.1。
2. Agent Soul 注入协议 v0.1。
3. Memory 配置规则 v0.1。
4. 董事会-CEO 协作与 OA 文档规程 v0.1。
5. 第 2 号决议重新接入建议。
6. 需要董事会确认的问题。

其中前四项是核心交付物。每份文件应短、准、可执行，优先约束行为和降低混乱，不追求抽象完整。

## 5. 董事会回报格式

CEO 回报董事会时，只上报：

- 四个核心资产的成稿或摘要。
- 关键组织判断。
- Memory 风险与边界。
- 第 2 号决议接入方式。
- 需要董事会拍板的问题。

不要提交：

- 内部 Kanban。
- 日常任务清单。
- Agent 调用细节。
- 常规排期。
- 未形成判断的过程材料。

## 6. 必须升级给董事会的事项

以下情况必须提交董事会确认：

- 调整董事会、Codex、CEO Agent 的基本权责。
- 新增、取消或重组 Hermes 核心 Agent 角色。
- 将 Memory 规则扩展到敏感信息、客户承诺、账号凭证或个人隐私。
- 建设超出文档系统范围的 OA 软件或自动化系统。
- 修改第 2 号决议目标、边界、交付标准或验收口径。
- 出现角色污染、越权承诺、成本失控或业务推进延迟风险。

## 7. CEO 内部拆解要求

CEO Agent 接收本任务后，应自行建立执行结构：

- 明确四个核心资产的责任归口。
- 复核现有 Hermes 团队设定。
- 归纳最小可用的 Soul 与 Memory 字段。
- 设计第 2 号决议重新接入路径。
- 标记董事会验收节点。

内部拆解以推进交付为目标，不需要回传董事会，除非触发第 6 节升级条件。
