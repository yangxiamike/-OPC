# CEO 任务输入：董事会第 1 号决议 - 基础运行系统试运行与反馈 v0.1

日期：2026-05-18
来源：董事会第 1 号决议
接收角色：Hermes CEO Agent
状态：待 CEO 试运行反馈
尺度审计：战役级任务输入。本文件用于完成董事会到 CEO 的试运行交接，不是制度制定授权，不是执行清单，也不是项目 Kanban。

## 1. 上位依据

请 CEO Agent 执行董事会第 1 号决议：

`../01_董事会决议/第001号_一人公司集团运行系统_v0.1.md`

董事会已确认：

- 第 1 号决议定义公司如何运行。
- 第 1 号决议的核心不是四个孤立资产，而是三套底层系统：OA 系统、Hermes Agent 系统、Hermes Agent Holographic Memory。
- 三套底层系统由董事长与托特秘书层审议确立，不下放 CEO 决策。
- 原外贸阀门工厂官网改造获客战役校正为董事会第 2 号决议。
- 第 2 号决议不作废，但需在第 1 号决议的运行系统下重新接入。
- 当前优先建设最小可运行系统，不建设完整 OA 软件。

CEO 任务输入不重复董事会决议内容，只说明试运行交接、权限边界和回报格式。

## 3. CEO 经营权限

CEO Agent 在董事会授权范围内自行管理：

- 在既定 Hermes Agent 系统下组织内部执行。
- 按既定 Soul 与 Holographic Memory 规则调用执行 Agents。
- 把董事会任务输入转化为项目 Kanban。
- 收集试运行中暴露的问题并回报董事会。
- 让第 2 号决议接入 OA 与 Hermes Agent 系统。
- 识别执行过程中的卡点、风险和需董事长拍板事项。

上述事项属于经营执行与试运行反馈，不需要作为过程材料提交董事会。

CEO Agent 不得自行改变董事会、托特秘书、CEO Agent 的基本权责，不得擅自扩建完整 OA 软件，不得把 Holographic Memory 设计为无差别资料仓库，不得自行改写 Hermes Agent 的 Soul 与协作规则。

## 4. 第一轮交付

CEO Agent 第一轮必须提交实质反馈：

1. 三套系统试运行反馈：OA 系统、Hermes Agent 系统、Holographic Memory 是否足以承接业务执行。
2. 第 2 号决议重新接入建议。
3. 执行过程中发现的权责冲突、文档断点、Holographic Memory 风险。
4. 需要董事会确认的问题。

CEO Agent 不需要提交“CEO 团队组织宪章、Agent Soul 注入协议、Memory 配置规则、董事会-CEO 协作与 OA 文档规程”的制度定稿。上述内容属于董事长与托特秘书层的制度资产，可由 CEO 在试运行后提出修改建议。

## 5. 董事会回报格式

CEO 回报董事会时，只上报：

- 三套系统的试运行结论。
- 关键组织判断。
- Holographic Memory 风险与边界问题。
- 第 2 号决议接入方式。
- 需要董事会拍板的问题。

不要提交：

- 内部 Kanban。
- 日常任务清单。
- Agent 调用细节。
- 常规排期。
- 未形成判断的过程材料。
- 对底层制度的自行定稿。

## 6. 必须升级给董事会的事项

以下情况必须提交董事会确认：

- 调整董事会、托特秘书、CEO Agent 的基本权责。
- 新增、取消或重组 Hermes 核心 Agent 角色。
- 将 Holographic Memory 规则扩展到敏感信息、客户承诺、账号凭证或个人隐私。
- 建设超出文档系统范围的 OA 软件或自动化系统。
- 修改第 2 号决议目标、边界、交付标准或验收口径。
- 出现角色污染、越权承诺、成本失控或业务推进延迟风险。

## 7. CEO 内部拆解要求

CEO Agent 接收本任务后，应自行建立执行结构：

- 按三套系统承接第 2 号决议。
- 复核现有 Hermes 团队设定在执行中是否足够。
- 按既定 Soul 与 Holographic Memory 规则运行最小闭环。
- 设计第 2 号决议重新接入路径。
- 标记董事会验收节点。

内部拆解以推进交付为目标，不需要回传董事会，除非触发第 6 节升级条件。
